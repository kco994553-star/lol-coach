## Interface and compatibility

LoadingPlanboard.evaluate(report,catalog,coach,planning?,knowledge?) => player-planboard-v1.
LoadingCoach.evaluate appends coach.planboard; old coach fields/periods/claims remain.
Inputv4 = exact inputv3 fields plus planning. planning has exact keys basis/overrides;
basis loading-plan-example-v1. Strict overrides:
- enemy_support PRESENT/ABSENT/UNKNOWN
- enemy_jungle UNKNOWN/AWAY/NEAR
- ally_jungle UNCONFIRMED/AVAILABLE
- goal AUTO/PRESSURE/FARM/RECALL
- clear_window UNCONFIRMED/OPEN
Old inputs default empty planning; no new required control. Planning and scenario are
hypotheses, never observations. The existing scenario remains lane-standard-v1 unchanged.
OPEN means a deliberately selected example with resources, opposing handling, current/
next wave and tower-reach opportunity; it is not inferred from fast-clear capability.

Result: schema_version, context, headline, lane, overall, operations, fight, reminders,
quick_scenarios, wave, choice, evidence. Lane contains overall_goal and milestone purpose;
wave contains purpose/state/conditions, pace/pressure/exposure/resources separately,
handling/position/combat/next_wave/change_if, three steps and diagram. state minion size/
reinforcement timing remain UNOBSERVED; no fixed counts. The diagram is an example,
not a current-wave recommendation or exact range/combat simulation.

Wave position/objective/available resources select an explicit plan. RECALL+OPEN+enough
resources may support FAST_PUSH then actual tower-arrival confirmation, never completed
CRASH. No open window => do not force clearing through threat. Incoming/under tower/
returning states remain distinct. Enemy jungle UNKNOWN/NEAR adjusts exposure and pressure;
it alone neither bans all trades nor forces one processing speed. Next-wave burden is
always stated. Optional support absence changes CS/space action, not guaranteed all-in.
An ally jungle connection is a possible link and never a predicted route.

Qualitative table remains source-scoped standard matchup comparison. Planning changes
execution context, not invented advantage. Preference changes only eligible action and
cost emphasis; metrics/evidence/skill mechanics do not change. Unknown stays unknown.

Overall shows TOP/MID/BOTTOM pairs and separately priority/link candidates; exact source
match only for a supported lane. Other lanes remain insufficient, not contested. Ally
CC→jungle follow-up are conditional mechanism links, not success/route rankings. L0
contains max two scenarios, no arbitrary weights or input-array importance.

Fight prioritizes threat classes by relation to own role/line vs flank, not arbitrary
scores. Distinguish minion/terrain blocking, exposure/targeted access, reserved escape,
and cutting follow-up after CC. One expended skill does not imply kill/chase advantage.
Skills use catalog champion/slot mappings; raw quotes unchanged. Support/ally contexts
are not transferred to distant-lane basics. Existing map geometry reused only for its
supported purpose; operations/line/map/zoom steps use same selection. No unknown enemy
position is invented; absent support omitted from line example, not relocated.
