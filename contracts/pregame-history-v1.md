# Additive bounded plan history contract

Queue v1.4 authorized production integration fix. GET /dev/v1/pregame/inputs/{id}/plan-history returns list of metadata only: id,session_id,revision,input_revision,created_at,validity,expiry_reasons,schema_version. Each stored result is checked with its own evaluator version and current dependencies before projecting validity; no source text or cooldown is promoted through metadata. GET /inputs/{id}/plans retains its original full body and operational body limit, individual /plans/{id} returns immutable content plus validity. UI history uses bounded metadata then individual fetch, so five large plans can be navigated under normal1MB cap; actual/synthetic browser fixtures keep samecap. Saved payloads and older API remain unchanged. Very large metadata lists still follow the declared operational limit; no unbounded response is created.
