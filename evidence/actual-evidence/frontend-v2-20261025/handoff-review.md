# Independent handoff review

Verdict: changes required. Reviewed the draft brief, implementation report, requested diff, adapter, loading integration, engine validation, and champion return-state consumer. Existing 81 focused tests and reported Chromium coverage were not rerun. Three additional targeted real Chromium reproductions confirmed the defects below.

## Ranked material findings

1. **P1 — Restoring an explicit plan does not preserve it for the champion round trip.** `web_r4/loading.js:128` (`restoreRoute`) validates and fills the explicit `#plan` but updates neither saved-plan nor draft storage. On a fresh session, opening a valid complete shared plan, navigating to `champion.html`, and clicking the real champion Apply CTA returns to a handoff based on an empty draft. With an older saved draft it instead uses that older input. Reproduction output: restored plan ally0 `오른`, saved draft `null`; after the champion CTA, ally0 and enemy0 both empty and a slot selector is required. Applying would lose the other picks and v3/v4 context. Persist the successfully restored canonical input, honoring explicit URL precedence, without changing its URL/period/detail. Cover a full document navigation through the real champion CTA, including an older stored draft.

2. **P2 — The new popstate wrapper drops the event and resets scenario/planning on Back.** `web_r4/loading.js:144` calls `restoreRoute()` without forwarding the event. Its existing `event.type === 'popstate'` same-plan branch consequently cannot preserve current edited input while closing a detail. Real Chromium: open a complete `#plan`, open lane detail, select quick `KEY_SPENT`, then browser Back. Before Back the URL input contains `scenario.overrides.enemy_key: 'SPENT'`; afterward `scenario` is absent. The pre-change listener passed the event directly. Forward the event and retain the existing history semantics; cover editing scenario/planning inside a detail and navigating Back.

3. **P2 — A PC import leaves an old preview applicable when session writes fail.** `web_r4/loading.js:558` (`importDraft`) changes the form and analyzes it without invalidating the open preview or changing `draftRevision`. With unavailable session writes, the storage snapshot remains null, so neither Apply race guard detects the change. Real Chromium: start blank `#handoff` for Caitlyn/BOTTOM, choose allies:3; import a valid complete PC draft with Fiora ally0; the page has `#plan` and Fiora but the old preview remains visible. Clicking its Apply replaces the full imported input with the original blank preview plus Caitlyn, yielding `#draft`, empty ally0/enemy0. Reproduction used a synthetic PC token/status and throwing Storage.setItem, not any actual PC service. Invalidate or regenerate preview and revision for programmatic form changes independently of storage. Confirm Apply cannot erase newly imported picks when storage is unavailable.

## Spec compliance

The pure UMD interface matches the requested intent/preview/apply contract, keeps five explicit slots per team, preserves unknown positions and scenario/planning in its normal adapter path, requires occupied-pick replacement confirmation, rejects cross-team duplicates, and retains strict complete-input analysis. Partial Apply replaces the route with `#draft` and does not analyze; Cancel itself does not alter URL or draft. Return targets are restricted to the two local champion pages, and detail_scroll/section conform to the current ChampionState contract. The three findings above prevent compliance with preservation, stale-preview safety, and existing route/history behavior end to end.

## Quality assessment

The adapter is isolated, immutable, defensive about keys/prototypes, and delegates scenario/planning validation to the existing validators. UI text is rendered through textContent. Targeted tests cover useful preservation and interaction behavior. The integration's state invariants are currently spread across form, report, revision, session, and history; mutation paths such as restored plans, Back, and PC import do not consistently synchronize them. The added failure-path browser cases should exercise those actual transitions rather than only adapter snapshots. No code edits, commits, or unchanged-suite reruns were performed in this review.
