# 출처에 연결한 지식 후보

2026-10-05. Frozen KNOWLEDGE/PERSISTENCE와 REC-REQ-012/REC-SC-015의 좁은
저장·조회 구현이다. 실제 경기 판단 검증이나 검토 완료 지식을 의미하지 않는다.

1. 기존 로컬 서버에 연결하고 **자료·복기 노트**에서 자료와 노트를 저장한다.
2. **지식 후보 → 현재 저장된 노트를 출처로 선택**을 누른다. 아직 저장하지 않은
   노트나 수정 중인 노트는 연결하지 않는다.
3. 직접 작성한 주장·저자와 적용 조건·필요 정보·작동 근거·반례·한계를 입력한다.
   모르는 조건은 UNKNOWN으로 남긴다. UNKNOWN은 적용 가능한 모든 조건이 아니다.
4. 새 버전을 저장한다. 저장된 버전을 조회·내려받고 수정하면 새 버전이 생긴다.
   이전 버전의 내용과 출처는 바뀌지 않는다. 다른 창에서 새 버전을 저장했다면
   충돌을 표시하고 현재 초안을 유지한다. 목록에서 최신 버전을 확인한 뒤 진행한다.

후보는 반드시 EXPLORATORY(탐색 단계)이며 coaching_enabled=false다. 검토 완료
상태로 올리거나 분석 엔진에 적용하는 API는 없다. 자료의 실제 내용·작성자의 주장·
플레이어 관찰·게임 패치 적용성은 서로 다른 검증 대상이다. 이 저장 기능이 어느
대상도 검증 완료로 승격하지 않는다. 실제 Decision/Coaching N은 0, 정확도는 null이다.

## 저장·삭제

한 후보 버전은 실제 저장된 VIDEO 또는 RAW_DIAGNOSTIC 자료의 노트 버전 하나를
참조한다. 서버가 그 보고서와 노트의 실제 저장 UTF-8 바이트 해시를 계산한다.
사용자가 해시·검토 상태를 보내 덮어쓸 수 없다. 노트가 이후 수정되어도 연결은
원래 저장 버전 그대로다. 여러 출처를 연결하는 규칙과 검토/퇴역 워크플로는 미지원이다.

rule_id와 version은 임의 식별자이며 순번·작성 시각·신뢰도로 해석하지 않는다.
다음 저장은 실제 최신 version을 비교한다. 기존 Frozen 형식대로 knowledge_rules는
(id,version) 복합 기본키와 status/payload를 가지며 원자료 노트 및 이전 규칙 버전을
실제 외래키로 참조한다. 자료 DB만 기존 schema1에서 schema2로 추가 전환한다.
기존 resources/note_history 행과 원래 ResearchStore 구현·합성 복기 DB는 보존한다.

출처 자료를 삭제하면 그 자료에 연결된 버전과 후속 버전이 같은 트랜잭션에서
삭제된다. 예를 들어 A(출처1)→B(출처2)→C(출처3)에서 출처2를 삭제하면 B·C가
삭제되고 A는 남는다. 출처3이 남았다고 C를 유지하지 않는다. 후보 자체를 삭제하면
전체 버전이 삭제된다. 삭제 기록에는 새 임의 식별자와 실제 삭제 개수만 남는다.
원문·주장·저자·출처 식별자를 삭제 기록에 복제하지 않는다.

화면과 내려받기는 실제 저장된 버전을 사용한다. 늦게 도착한 저장/조회 응답이나
출처 삭제 확인이 다른 편집 문맥을 바꾸지 않도록 요청 소유권을 확인한다. 삭제된
저장 내용은 표시·내려받기에 남기지 않는다. 별도로 연결한 독립적인 새 초안의
보존 범위와 실제 삭제 영향은 자동 코칭 검증과 별개로 브라우저에서 검사한다.

## 전환 전 복구

schema1→2의 변경문 실행 전에 실제 자료 DB 복구 사본을 생성한다. 쓰기 예약 잠금
동안 별도 읽기 연결로 복사하고 기존 스키마·내용·전체 행·해시·크기를 확인한다.
같은 폴더의 `.pre-knowledge-v2-<임의ID>.sqlite` 사본은 POSIX 0600이며 기존 파일을
덮어쓰지 않는다. 사본 생성 실패는 전환을 중단하고, 이후 변경 실패는 원본을
schema1로 되돌리면서 검증된 사본을 남긴다. 정상 schema2 재시작은 사본을 추가하지 않는다.

사본은 전환 전 개인 노트도 포함한다. 이후 웹 삭제가 사본이나 별도 ZIP 백업을
수정하지 않으므로 보관·삭제를 사용자가 관리한다. 전체 운영 데이터는 기존 두 DB
[백업·복원 명령](MVP_BACKUP.md)을 사용한다. 자동 전환 사본은 자료 DB 하나의 복구
사본이며 전체 두 DB ZIP과 혼동하지 않는다. 실제 사용자 원문은 GitHub에 게시하지 않는다.

## 검증 범위

실제 PR6 브라우저 최초 실행37268245767은 과거 버전 다운로드 바이트 비교에서
실패했다. POST 응답은 생성 순서의 JSON 객체이며 저장 후 GET은 정렬된 키 순서다.
다운로드의 정확한 바이트는 실제 조회한 저장 객체에 연결하고, 생성 응답과의 내용
동일성은 별도로 확인해야 한다. 최초 실패·검사 원본·수리 기록을 보존하며 API나
저장 데이터·Unicode(다국어 문자)·수정 초안 제외 조건을 완화하지 않는다.

저장42·추가 백업19·HTTP5 테스트와 기존 필수 회귀를 실행한다. 순수 Node VM 삭제
반례와 실제 Chrome/HTTP/SQLite 검사는 별도 증거다. 기존 최초 실패·중간 수정 결과를
보존한다. 원본 source/note 해시는 바이트 동일성을 검증하며 독립 참조의 정답성을
인증하지 않는다. PLAYER 참조와 행동 전 문맥이 없으면 해당 검증만 PARKED_EXTERNAL이다.

최초 삭제 반례 0/3→3/3, 중간 저장 확인·오류 반례 각각 0/1→1/1, 이후 조회 반례
0/2→2/2와 후보 자체 삭제의 추가 반례 0/1→1/1을 별도 실행 기록으로 남긴다. 최초 두 개발 중 JS 버전은 바이트
사본이 보존되지 않아 해당 원본 코드를 다시 실행할 수 있는 증거로 주장하지 않는다.
당시 실제 실행의 코드·검사·입력 해시와 실패 상태는 보존한다. 이후 조회 반례의
부모 JS는 실제 바이트 사본과 해시를 보존하고, 현재 코드로 모든 고정 반례를 재실행한다.
