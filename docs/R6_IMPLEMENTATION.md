# R6 — 기존 웹과 자료·복기 노트 통합

2026-10-04 KST. 위험 DEEP. R3 코어, 동결 설계, 과거 증거 유지.
R6는 기존 합성 분석 웹에서 R5의 데이터 진단과 영상 후보를 함께 이용할 수 있게 한다.

## 사용자 흐름

1. 기존 실행 명령(docs/R4_IMPLEMENTATION.md)으로 로컬 서버 시작 후 접속키 입력.
2. 합성 분석: 기존 사례 저장→분석→재열람 흐름 유지.
3. 자료·복기 노트: 공식 응답 예제 또는 공개 영상 후보를 선택.
4. 영상은 주제 필터→시간 링크로 원본 열기→후보별 노트 작성.
5. 당시 확인 근거·의도·다른 선택·사후 결과를 각각 저장하고 재열람·내려받기.

원본 JSON 또는 지원 시간표시 자막 TXT도 로컬 서버에 불러올 수 있다.
API는 원본을 진단·색인한 뒤 결과만 저장하며 원본 전문은 저장하지 않는다.
자료 이름(파일명)과 작성 노트는 로컬에 남으므로 불필요한 개인정보를 넣지 않는다.
자료와 전체 노트를 삭제할 수 있다. 외부로 내려받은 파일은 별개다.

## 저장·API 계약

- 기존 DB와 별도의 `<db>.research.sqlite`를 사용한다. 기존 스키마 자동 변경 없음.
- 자료 ID는 종류와 보고서의 정규화 해시. 같은 자료는 중복 저장하지 않으며 최초 제목 유지.
- 보고서는 서버가 R5 코드로 생성한다. 사용자 JSON의 검증 완료·코칭 활성 주장은 채택하지 않는다.
- 노트는 `overview` 또는 실제 후보 cue_index에만 연결한다.
- 노트 revision은 증가하고 기존 이력을 남긴다. expected_revision 충돌은409, 덮어쓰지 않는다.
- 현재 API/UI는 최신 노트를 표시한다. 과거 revision 선택·복원 UI는 아직 없다.
- 한 노트는 네 문자열 필드 각각 최대2,000자. 사용자 노트는 검증된 경기 근거로 자동 승격되지 않는다.
- 인증/Host/Origin/CSP/요청 크기 제한은 기존 웹 서버 규칙 적용.
- source와 notes는 삭제 시 연쇄 삭제된다.

| 경로 | 동작 |
|---|---|
| GET/POST /dev/v1/research | 자료 목록·진단/색인 생성 |
| GET/DELETE /dev/v1/research/{id} | 자료 조회·전체 삭제 |
| GET/PUT /dev/v1/research/{id}/notes/{anchor} | 최신 노트 조회·새 버전 저장 |

POST의 source_type은 official_sample, video_example, raw_json, transcript.
기존 Store.backup은 합성 분석 DB만 포함한다. R6의 두 DB를 모두 보관하려면 서버 종료 후 두 파일을 복사한다.
