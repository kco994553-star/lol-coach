## 문서 역할

| 문서 | 책임 |
|---|---|
| 기능 명세 | 2.1~2.7 제품 계층·역할·완료 기준 |
| 데이터 계약 | 입력·지식·자료구조·버전 |
| 처리 흐름 | 생성 단계·모듈 연결 |
| 출력 계약 | 고정된 결과 형식·표현 |
| 판단 규칙 | 조건·근거·대안·검토 상태 |
| 검증 사례 | 입력·기대 판단·반례 |
| 완료 기준 | 검사와 증거·미검증 범위 |

## 공통 마크다운

상단에는 버전·기준일·상태를 둔다. 목적 → 확정 계약 → 구현 상태 → 반례·검증 → 다음 작업 순서로 작성한다. 제목은 2단계와 3단계를 중심으로 짧게 쓴다. 파일명과 필드는 인라인 코드, 비교는 표, 의존 구조는 Mermaid를 사용한다. 체크박스는 실행 과제에만 사용한다.

제품 기능 번호는 화면 컴포넌트나 내부 모듈 번호가 아니다. 내부 엔진 추가를 이유로 정해진 출력에 새 카드·행·행동을 추가하지 않는다.

## 항목 템플릿

기능: ID / 사용자 질문 / 입력 / 판단 / 출력 연결 / 전환 조건 / 반례 / 완료 기준.
규칙: ID / 버전 / 단계 / 관련 인원 / 필수 조건 / 제외 조건 / 판단 / 근거 / 충돌 / 대안 / 검토 상태 / 반례.
사례: case_id / 목적 / 입력 / 가정 / 자료 패치 / 규칙·표현 버전 / 기대 판단 / 출력 위치 / 금지 주장 / 반례 / 검증 종류.

구현됨·부분 구현·설계·미구현을 구분한다. 소프트웨어 통과, 콘텐츠 근거, 전술 타당성, 화면 검증, 실전 효과를 합치지 않는다. 자동 조합 입력을 실시간 전장 관측으로 표현하지 않는다.

## 다음 구현 대기열

1. 조건의 대상·시점·출처 계약.
2. 입력 충돌과 단순 결측 구분.
3. 규칙 ID·버전·채택 상태 계약.
4. 적용·제외 규칙 기록.
5. 규칙 충돌의 명시적 처리.
6. 후보별 실행 조건과 비용 연결.
7. 기본안·대안·판단 제한 구분.
8. 기본 방향의 유지·강화·부분 수정·전환 분류.
9. 같은 팀에서 사용자 역할 변경 회귀.
10. 카이사/직스·카르마의 비전투 손실 사례.
11. 기술 습득·가용성 조건의 사례 확대.
12. 서포터와 원딜의 공동 실행 조건.
13. 탑·미드의 라인 운영 고유 조건.
14. 정글 성장·지원·방어 기회비용.
15. 운영 여섯 후보의 비교 계약.
16. 한타 진입·호응·중단·재진입 조건.
17. 다대다 상호작용의 범위와 한계.
18. 전체 조합 비교표 4행/목표 판단 5행 대응 정리.
19. 모든 규칙의 패치 의존 인덱스.
20. 동일 사례의 자료 버전 전후 비교.
21. 과거 버전 실행·복원 계약.
22. 자료 편집 도구와 검증 오류 안내.
23. 자동 입력 공급자의 실제 필드·시점·권한 확인.
24. 수동/자동 입력 공통 어댑터와 충돌 정책.
25. 자동 연결 실패·재연결·수동 전환 검사.

각 항목은 구현·반례·완료 근거를 함께 남긴다. 앞선 데이터 분리와 고정 전달 계약은 전체 규칙 엔진 완성을 뜻하지 않는다.
