# Codex 게임플랜 2+3 장기 실행 프롬프트 v1
아래 전체를 Codex 작업 지시로 사용한다. 새 대기열 ID는 GP23-01~44이며 과거 queue-44의 완료 이력을 계승하지 않는다.

## 임무와 권한
kco994553-star/lol-coach의 최신 main에서 시작한다. 사용자 승인 방향은 docs/gameplan-content/gameplan-2-plus-3-v1.md를 따른다.
목표는 2+3 게임플랜의 설계 불명확성을 해소하고, 가능한 범위를 구현·검증해 근거와 함께 인계하는 것이다.
기존 AGENTS.md, 고정 계약, 사용자 변경 사항, 지식 검토 이슈 보호 규칙을 먼저 읽는다. 관련 없는 리팩터링·전술 승인·전체 후보 자동 승격을 하지 않는다.
현재 코드가 이미 해결한 작업은 증거를 확인하고 재사용한다. 과거 체크 수나 배포 결과를 새 작업의 성공으로 복사하지 않는다.
일반적인 가역적 구현 판단은 스스로 결정하고 기록한다. 외부 권한·비용·보호된 사용자 결정이 필요하면 해당 의존 작업만 BLOCKED로 두고 다른 준비된 작업을 계속한다.
배포는 현재 세션의 배포 권한과 저장소 절차가 허용할 때 수행한다. 권한이 없다면 검증된 PR·배포 준비물을 끝까지 만든다. 강제 푸시·검사 우회·관련 없는 삭제는 금지한다.

## 실행 및 상태 기록
docs/gameplan-content/gameplan-2-plus-3-status.md를 만든다. 각 작업에 ID, 의존성, 상태, 변경 파일, 결정/반례, 실행 명령과 결과, 남은 위험, 다음 작업을 기록한다.
상태는 TODO / IN_PROGRESS / DONE / PARTIAL / BLOCKED / DEFERRED이다. 문서 작성, 코드 구현, CI, 브라우저, 실경기, 배포 상태는 별도 열로 기록한다.
기본 실행 순서는 아래 번호순이며 각 묶음은 앞 묶음의 계약에 의존한다. 아래의 '통과'는 최소 수용 기준이다.
한 묶음이 끝날 때 검토하고 유효한 다음 작업을 계속한다. 장애를 반복 조회하며 멈춰 있지 않는다. 컨텍스트 종료 전 현재 SHA·명령·미완료·재개 지점을 저장한다.
한 번의 실행에서 시간/환경 제한으로 남은 작업이 있으면 완료를 과장하지 말고 정확한 재개 지시를 남긴다.

## 냉철한 검토 체계
각 설계·구현 묶음 전후에 다음을 수행한다.
1. 사용자가 얻는 구체적 판단이 무엇인지 한 문장으로 정의한다.
2. 기존 코드·데이터·화면·실제 출력에서 근거를 찾는다.
3. 반례 최소 2개를 만든다: 정보 누락/오래된 정보 하나, 목표 충돌/잘못된 일반화 하나.
4. 유지 / 추가 / 제거 / 수정 / 보류 중 판정한다. 제거는 중복·무근거 규칙·죽은 경로 등으로 한정하고 사용자 승인 요구를 조용히 삭제하지 않는다.
5. 비용·의존성·실패 영향·검증 방법과 재개 조건을 기록한다.
6. 고친 후 같은 반례를 재실행하고 회귀를 검사한다.
검토 대장 필드: 문제ID / 근거 / 확정 요구 또는 구현 제안 / 반례 / 심각도 / 판정 / 변경 범위 / 수용 기준 / 상태 / 증거.
P0: 허위 관측·출처/승인 조작·계약 손상. P1: 위험한 판단 모순·핵심 사용자 흐름 실패. P2: 제한적 누락·사용성. P3: 선택 개선.
P0/P1은 영향받는 출시를 막고 독립 작업은 계속한다. P2/P3는 근거와 제한을 남겨 우선순위를 정한다.
첫 검토 → 수정 → 재검토를 기본 1회로 운영한다. 새 중대 결함이 있을 때만 추가 순환한다. 증거 없이 '문제 없음'으로 종료하지 않는다.
매 묶음마다 '더할 것 / 뺄 것 / 고칠 것 / 지금 하지 않을 것'을 적되, 없는 변경을 억지로 만들지 않는다.

## 완료 기준과 보고 형식
최종 보고는 '무엇이 바뀌었는가 / 무엇을 검증했는가 / 아직 못 하는 것은 무엇인가 / 다음 작업'으로 쓴다.
기능계층 진행률은 명시한 분모와 행별 근거로만 갱신한다. 검색 지원 수, 기본 프로필 수, 전술 지원 수, 실경기 평가 수를 분리한다.
필수 설계 결정이 해결됐다는 사실과 구현이 끝났다는 사실을 분리한다. 기존 지식 검토 이슈를 승인하거나 닫지 않는다.
검증된 작은 변경을 완료하고 다음 준비된 작업으로 계속 진행하라. 사용자가 이미 정한 2+3 방향을 다시 묻지 말라.
