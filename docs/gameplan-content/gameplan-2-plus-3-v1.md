# 게임플랜 2+3 설계 보충 v1
기준일: 2026-10-25. 상태: 사용자 방향 승인 / 세부 계약은 아래 구현 제안 / 신규 구현·배포·실경기 검증 미완료.
기준 저장소: kco994553-star/lol-coach, 검토 시작 main 523c983257197182880a18a055e3a9ba98ccec78.
기능계층 v2.0의 160행과 번호를 보존한다. 게임플랜은 3번이다. 기존 대기열 44개와 이 문서의 새 대기열은 별개다.

## 사용자 확정 방향
상단 2개는 **전체 조합 방향**, **사용자 기본 방향**이다. 하단 3개는 **라인전 / 운영 / 교전·한타**이다.
전체 조합 방향은 양 팀의 승리 방식·장점·제약·주요 위험, 사용자 기본 방향은 내 목표·역할·기본 라인관리를 설명한다.
정글 사용자에게 라인전은 초반 정글, 운영은 중반 운영으로 번역한다.
기존 비교표, 단계별 행동 5개, 항상 보이는 코칭 문장, 접힌 상세 설명은 유지한다. 같은 문장을 상하단에 반복해서 분량을 채우지 않는다.
교전은 5v5뿐 아니라 1v1/2v2, 갱·역갱, 강·정글 싸움, 잘라먹기·추격, 오브젝트 전투를 포함한다.
교전 설명 순서는 **내 목표 → 주요 위협 → 의식할 대상·위치 → 행동 → 전환·중단 조건**이다.
원딜은 자신에게 닿는 위협을 인지하고 공격할 공간·시간을 확보한다.
탑 탱커는 적 딜러의 접근·공격을 방해해 딜로스를 만들 수 있어야 한다. 다만 아군 보호와 적 딜러 방해 중 무엇이 필요한지는 상황으로 판단한다.
짧은 보라색 태그는 판단 결과를 빠르게 전달한다. 태그만으로 설명을 대신하지 않는다.

## 설계 선택과 책임
기존 공통 판단 계약을 확장하는 방식을 기본 구현안으로 삼는다. 모든 조합을 개별 문장으로 하드코딩하는 방식은 유지 비용과 누락 때문에 채택하지 않는다. 별도 AI 호출로 매번 자유 생성하는 방식은 출처·재현성·계약 검증 부담 때문에 필수 경로로 두지 않는다.
이 기술 선택은 작성자의 구현 제안이며, 사용자가 모든 필드·알고리즘을 승인한 것으로 기록하지 않는다.
문구 교체만으로 완료 처리하지 않는다. 입력 → 조건 판단 → 계획 → 태그 → 화면 → 근거가 같은 계약을 따라야 한다.

## 라인관리 판단 계약
기본 방향은 조합과 챔피언 특성에 따른 조건부 계획이다. 상황별 판단은 확인한 정보를 입력했을 때 기본 방향을 제한하거나 전환한다.
필수 입력 후보: 양쪽 정글의 정보 상태·마지막 확인 시각·지역, 현재 웨이브 방향/크기/위치와 조작 가능성, 체력·마나·핵심 기술 정보, 아군 합류 가능성, 상대 위협, 귀환·오브젝트 목적.
정보 상태는 observed / assumed / unknown / stale을 구분한다. observed에도 출처·관측 시각을 기록한다. assumed는 사용자가 선택한 가정이며 실제 관측으로 표시하지 않는다. 신선도 기준은 데이터별로 정의하고 근거 없는 단일 초 단위를 적용하지 않는다.
로딩 화면은 실제 정글 위치·스킬 보유·도착 시간을 만들어내지 않는다. 확인할 수 없는 정보는 unknown이다.
판단 순서: 정보 신뢰성 → 당장 가능한 웨이브 행동 → 갱/다이브/교전 위험 → 우리 지원 가능성 → 얻을 이익과 기다리는 비용 → 선택과 전환 조건.
선택 후보는 받아먹기 / 당기기 / 유지 / 느린 푸시 / 빠른 푸시 / 밀어 넣고 리셋이다. 모든 후보가 모든 웨이브에서 가능하지 않다.
적 정글 근처라도 큰 웨이브를 방치하면 다이브 위험이 커질 수 있다. 적 정글이 반대편이어도 상대 라인 위협·자원·합류 때문에 푸시가 불가능할 수 있다.
양 정글 미확인에서는 무조건 푸시나 무조건 당기기를 권하지 않는다. 현재 웨이브와 노출 경로에 맞춰 허용 범위를 제시한다.
딜교와 웨이브는 연결한다: 교환 길이, 스킬을 미니언에 사용할 비용, 추격 범위, 체력 손실로 다음 웨이브를 잃는 비용을 설명한다.
출력은 선택 행동·이유·금지 조건·전환 신호를 포함한다. 숫자로 계산할 근거가 없으면 정밀한 성공률·ETA를 생성하지 않는다.

## 교전·한타 판단 계약
위협 후보는 상대 이름 목록이 아니다. 도달 가능성, 참여 가능성, 알려진 자원/기술, 지형, 사용자에 대한 영향을 평가한다. 모르는 기술 상태를 사용 가능/불가능으로 확정하지 않는다.
명목상 인원수가 아니라 실제 공격·보호·합류에 기여할 수 있는 인원과 도착 순서를 구분한다.
내 목표와 팀 목표를 연결한다. 목표 예시는 생존하며 지속 공격, 아군 딜러 보호, 적 딜러 공격 중단, 핵심 대상 분리, 지역 확보, 유리한 철수이다.
탱커의 적 딜러 방해는 무조건 깊이 진입하라는 뜻이 아니다. 아군이 공격할 수 없는 진입, 보호 대상 방치, 추격으로 오브젝트를 잃는 상황을 반례로 검사한다.
교전 행동에는 진입/대기/거리 유지/차단/보호/추격 중단 등 선택과 그 조건이 있어야 한다. 무조건 싸움 회피도 불합격이다.
화면 기본 정보는 목표·상위 위협·즉시 행동이며, 상세에 후보 비교·근거·불확실성·대안·중단 조건을 둔다. 실행과 전환의 핵심 문장은 접지 않는다.

## 태그 정책 — 구현 제안
카드당 최대 2개를 기본값으로 검증한다. 1개는 목표/행동, 1개는 결정에 영향을 주는 위험/조건을 우선한다. 없는 정보를 채우려고 태그를 만들지 않는다.
예: 라인전 '짧은 교환', '정글 미확인'; 운영 '밀고 합류', '사이드 압박'; 교전·한타 '진입기 주의', '딜러 보호', '딜로스 유도'.
태그는 최종 판단에서 파생한다. 선택한 가정은 가정임을 같은 화면에서 드러낸다. 상태 변경 시 낡은 태그와 설명을 함께 제거한다.
상단 기본 방향과 하단 행동의 모순, '푸시'와 '당기기'의 동시 활성, 과도한 추상 태그를 검출한다.
글자 수·대비·모바일 줄바꿈은 실제 화면에서 검증 후 확정한다.

## 현재 한계와 검증 경계
현재 문서 기준 기본 프로필 4개는 REFERENCE_ONLY / TACTICAL_UNREVIEWED이다. 검색 가능 챔피언 수를 전술 지원 수로 바꾸지 않는다.
과거 CI·브라우저·배포 성공은 새 2+3 판단의 정확성 증거가 아니다. 실경기 코칭 효과는 UNMEASURED이며 표본 0을 유지한다.
새 출력 원문 5건은 엔진 실행 결과와 입력·버전·지원 범위를 묶어 저장한다. 부족한 경우도 그대로 공개하며 손으로 개선한 문장을 엔진 출력으로 위장하지 않는다.
