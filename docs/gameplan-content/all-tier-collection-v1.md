## Bounded acquisition

A schedule chooses one leaf tier/division target from a deterministic 40-slot rotation, using UTC epoch day modulo 40: tier varies over ten consecutive slots, then division advances I–IV. Manual dispatch can select any admitted leaf and division. MASTER, GRANDMASTER and CHALLENGER use their official apex list endpoints, which ignore division; repeated apex slots do not imply division coverage. Lower tiers use the official tier/division entries endpoint. Each job currently samples at most page 1 and 40 seed accounts. This is convenience sampling, not complete divisions/pages or a random ranked population.

Each run keeps the existing maximum 650 total requests (including retries, match details, timeline and static catalog), 300 in-scope match work items (legacy collection keeps its original accepted-pair ceiling), 40 players, one league page, two retries and 900-second deadline. Out-of-patch or missing match-detail responses still consume the shared request budget and do not consume the in-scope match ceiling. The same collector request counter, pacing state and deadline cover new power pairs and result backfill; no per-tier loop multiplies these limits. Conservative 20/second and 100/120-second pacing and provider response/header waits remain. The first 401 or 403 immediately stops that execution without retry. 429 Retry-After is bounded by retries, request count and deadline. Existing free-only/no-paid-fallback, quota and entitlement policies remain unchanged.

## Private result companion and completeness

`--matchup-results-state` persists the separately versioned `champion.opponent-results.v1` anonymous companion, validated through `coach_v1.matchup_results`. `--result-completeness-ledger` persists `champion.result-completeness.v1`: a digest of that exact validated dataset and its sorted complete result hashes. Both must agree before provider work. The result ledger is independent of the power accumulator's known hashes. Missing, conflicting or malformed result evidence never marks a match complete.

An already fetched match/timeline pair yields final-result evidence with no extra provider call. A power-known match whose result is absent remains eligible for bounded detail-only backfill; it fetches official match details without another timeline. New result evidence requires validated participant/team result booleans, queue/map/patch/duration semantics and anonymous roster projection. Victory is never inferred from resources, kills, frame order or a power archive. Fully complete power/result records already admitted to the current tier skip match-work slots, so later missing results can progress across runs. Invalid attempts remain incomplete and can be retried under a future authorized bounded run. Result omissions count collection attempts, not unique population exclusions.

A known anonymous result may be reused when another admitted seed cohort's official match-ID listing discovers the same match. Its identity remains the stable SHA256 match hash; seed membership and allowlisted provenance are merged separately. Provenance retains the admitted leaf, sampled division (null for apex), retrieval time/window and a safe run digest. Conflicting patch, roster or winner records fail closed before output. Unknown observed roles remain unknown in the private companion and do not create eligible role-specific statistics. A complete final result does not mean every requested statistical view is eligible.

The cumulative result companion and digest ledger live only in the private `power-state` artifact alongside the original power sufficient state, retained for 90 days and restored together. They never enter the seven-day public aggregate artifact or static browser roster assets. The CLI rejects private result paths inside its public aggregate directory. Public diagnostics can contain safe counts and acquisition status, never per-match rosters, provider identifiers, raw responses or keys. New private state starts empty; the 50/275 existing power samples are not silently declared final-result samples.
