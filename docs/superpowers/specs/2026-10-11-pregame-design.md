# 5개 포지션 경기 전 게임플랜 설계

권한/제품 목표: USER_QUEUE_V1.1_2026-10-11. 개인용 경기 전 준비→직접 플레이→경기 후 복기.
사용자 지시가 설계 구체화·무료 선택·병렬 실행·병합을 사전 승인한다. 단계별 재승인을 요구하지 않는다.
Frozen/legacy/기존 증거와 실제 경기 차단을 보존한다. 자동 지식 승인과 실시간 쿨타임은 구현하지 않는다.

## 흐름
기존 픽창 기록 선택 또는 10슬롯 수동 입력→별도 내 포지션/챔피언·룬·주문·출처 보완→
확장 입력 불변 저장→현재 REVIEWED 구조화 지식만 평가→7영역 게임플랜 저장→카드에서 입력·
규칙 버전·출처·제외 이유 조회. 승인된 자료가 없는 셀은 미확인이다.
1~3 공통 결과는 내 포지션을 바꿔도 동일, 4~6은 포지션별 규칙을 사용한다.
원본 픽창 저장본 전체와 해시를 보존한다. 포지션 후보를 확정 역할로 바꾸지 않는다.

## 실행 조건
자유 문자열을 해석하지 않는다. 선언된 필드/연산자/열거형과 정확한 패치 목록만 사용한다.
충족/불충족/미확인 3값, 필수 입력/반례/중단/충돌과 적용 이력을 보존한다.
챔피언 유형은 승인된 프로필에서만 파생한다. 프로필 부재는 UNKNOWN이다.
계획 문장은 승인된 원문 그대로 사용하고 조건/대안/한계를 함께 표시한다.
HP/웨이브/실제 스킬 상태처럼 관측되지 않은 조건은 실제 충족을 주장하지 않는다.

## PR10 연결
구조화 spec은 Research RAW_DIAGNOSTIC의 별도 rule-source.v1 자료에 불변 저장한다.
자료는 실제 게임 API 응답이 아니라 출처가 있는 지식 후보 명세다. 노트와 후보를 기존 저장 경로로 생성한다.
후보 required_fields에 명세 해시를 연결하고 claim/patch/applicability가 명세와 정확히 같아야 한다.
웹에서 명세·출처·패치·반례를 본 뒤 사용자가 기존 PR10 승인 버튼/확인 흐름을 실행한다.
AI는 EXPLORATORY 후보까지만 생성한다. 기존 자유문 지식은 자동 변환하지 않고 UNBOUND로 보류한다.
현재 head가 REVIEWED인 후보만 사용한다. 최신 수정/거절/삭제는 이전 승인 계획을 만료시킨다.

## 저장/운영
별도 .pregame.sqlite는 확장 입력과 계획만 저장, SQLite 트랜잭션·CAS·멱등성 키·불변 이력.
픽/패치/내 포지션 및 어떤 입력 변경도 이전 계획을 만료하고 새 입력 revision을 만든다.
계획 조회 때 입력 revision과 현재 지식 fingerprint를 비교한다. 만료 이력은 원문으로 보존한다.
백업은 기존 format1 보존, 새 sidecar의 검증된 export/import로 독립 복구한다.
새 PregameWorkbench는 기존 인증·Host/Origin·본문 제한을 그대로 상속한다.

## 검증
입력 누락·후보 역할·부분 룬·잘못된 패치·조건 충돌·미승인/자유문 지식·버전 변경·포지션 변경,
멱등 재시도·CAS·재시작·재조회·원본 출처 해시와 복구를 검사한다.
Golden10은 패치 null로도 저장/계획/미확인 근거 조회를 실제 브라우저에서5회 수행한다.
별도 합성 REVIEWED fixture로 공통 동일/포지션 행동 상이·타입 조건·쿨타임 표시 경계를 검사한다.
합성 승인은 격리 테스트 DB에만 존재하고 실제 사용자의 승인/코칭 정확도로 집계하지 않는다.
