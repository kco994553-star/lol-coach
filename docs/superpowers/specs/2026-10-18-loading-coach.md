## Data and review

web_r4/loading-knowledge.json contains format/version/checked_at/official_patch,
source records and matchup objects. Each source retains originalURL/author/credential
provenance/date or null/patch namespace/actual brief quote+locator/hash/access/limits.
Original research A/B/C/D JSON preserved under evidence; no raw videos/audio/subtitles.
Claim source check, mechanical fact check, tactical interpretation and real effect are
separate fields. `GUIDE_BASED` means scoped qualitative guide content checked against actual
excerpts, conditions and relevant archived mechanisms; not expert endorsement/current
numerical proof. AI extensions remain `DESIGN_HYPOTHESIS`. Each claim has counterexamples,
patch risks and source refs. Old statements and contradictions remain in research records.
No automatic equivalence between guide26.x and DataDragon16.x without mapping evidence.

## Pure interface

LoadingCoach.evaluate(report,catalog,scenario?) => loading-coach-v1 result. Node uses the
same JSON via require; browser receives catalog.coaching_knowledge after one fetch. No IO
inside evaluate. LoadingStrategy.analyze appends `coach` without changing legacy outputs.
Nested contract versioned; existing inputv1/v2 works with default standard. Inputv3 adds
`scenario:{standard:'lane-standard-v1',overrides:{...}}` with strict keys/enums; preferences
remain independent. Observations include draft picks/roles only; no resource/enemy position
observation is created from standards or controls.

Standard: same level within milestone, high/enough health/resources, equal starting-item
stage (not equal acquired gold), representative learned spells, neutral contestable wave,
ordinary spacing, no outside intervention. Per-judgment conditions still apply. First recall/
core are purchase milestones, not levels or fixed times. Unpriced/source-only builds do
not establish item equality or relative damage. Options UNKNOWN preserve uncertainty.
Scenario overrides: enemy_key AVAILABLE/SPENT/UNKNOWN; engage NONE/THEIRS/OURS/UNKNOWN;
resources SUFFICIENT/LOW/UNKNOWN; wave EVEN/BUILDING/INCOMING/UNDER_TOWER/RETURNING/UNKNOWN;
start_skill W/Q/E/UNKNOWN (C only). Other conditions stay standard, not observed.

Result fields: schema_version,supported,matchup_id,title,context,summary,periods,growth,
selected_period,selected,wave,trade,sustain,exceptions,actions,selection,evidence,lesson.
context separates observations/assumptions/preferences/patch status. summary provides
our_plan,enemy_plan,strong_phase,role,lane,fight,exceptions(max3). periods exactly six base
milestones {id,label,kind,metrics,reason,action,exception}; metrics PUSH/SHORT/EXTENDED/ALLIN/
ATTRITION each {assessment:ALLY|ENEMY|CONTESTED|INSUFFICIENT,scope,reason,claim_ids}.
No source => INSUFFICIENT. Preference cannot alter metrics/evidence/feasibility.
growth adds named events, not forced2/3core ticks. Events contain change,before,after,
remaining_strength,exceptions,global_reversal and positional_punish_risk separately.
selected carries five trade types; preferred length vs actual matchup advantage vs kill
vs chase remain separate. Enemy means persist after one key use; firsthit/CC isn't an
automatic retreat. sustain actors include carry/support separately, damage prevention vs
in-fight heal vs between-trade recovery, consumables/resources/CS downtime and uncertainty.
wave separates can_push/should_push and8 distinct plan candidates (unsupported retained).
Each plan includes goal/start/processing/skills/reserve/complete/abort/next/punishment/
conversion; no fixed minion count/time/casts. Preference selects only eligible supported
alternatives, retains same choice with reason where necessary. UNKNOWN doesn't unlock.
