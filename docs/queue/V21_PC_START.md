# LoL Coach PC 시작

Windows에서는 `Start-LoL-Coach.cmd`를 두 번 클릭합니다.
Python이 없으면 현재 Windows 사용자용으로 설치하고, 프로젝트 안 `.venv-pc`에 고정 버전 의존성을 설치합니다.
바탕 화면에 `LoL Coach PC` 바로가기를 만들고 로컬 서버와 브라우저를 엽니다.
처음 실행은 인터넷 연결이 필요하며, 이후 공식 자료 갱신 실패 시 저장된 자료와 수동 입력을 사용합니다.
실제 Windows 설치·바로가기·League 클라이언트 연결은 이 Linux 환경에서 검증하지 않았습니다 (`BLOCKED_EXTERNAL`).

프로젝트 폴더를 먼저 압축 해제하고 위 시작 파일을 실행하세요. 폴더를 이동하면 시작 파일을 다시 실행해 바로가기를 갱신합니다. 실행 창은 앱이 동작하는 동안 열어 둡니다. 종료는 창에서 `Ctrl+C`입니다. 포트가 사용 중이거나 앱이 이미 켜져 있으면 기존 창을 종료하거나 `-Port 8766`을 사용합니다.

## 선택 실행

```powershell
# Python이 이미 있는 경우 시스템 설치 없이 실행
.\Start-LoL-Coach.ps1
# Windows 로그인 시 자동 시작하는 현재 사용자 바로가기 추가
.\Start-LoL-Coach.ps1 -StartAtLogin -CreateShortcut
# 브라우저 없이 다른 포트에서 실행
.\Start-LoL-Coach.ps1 -NoBrowser -Port 8766
# 로컬 클라이언트 경로와 인증서 지문을 명시하여 연결
.\Start-LoL-Coach.ps1 -LcuLockfile 'C:\Riot Games\League of Legends\lockfile' -LcuCertificateSha256 '<SHA256>'
```

로그인 자동 시작을 해제하려면 Windows 실행 창에서 `shell:startup`을 열고 `LoL Coach PC.lnk`만 삭제합니다. Python 설치는 현재 사용자 범위이며, 프로젝트 의존성은 `.venv-pc`에만 설치합니다. 시작 도구는 관리자 권한을 요구하지 않습니다. `winget`이 없으면 python.org에서 Python 3.13을 설치하고 다시 실행합니다.

## 로컬 데이터와 접속키

기본 저장 위치는 `%LOCALAPPDATA%\LoL-Coach-PC\private`입니다. Windows 시작 도구는 이 폴더를 현재 사용자와 SYSTEM만 접근하도록 설정합니다. 저장 위치는 `-DataDir`로 바꿀 수 있습니다. 접속키는 매 실행 새로 발급하고 이 폴더의 `access-token`에 보관합니다. 브라우저는 `/pc#token=...` fragment로 키를 전달받은 직후 주소에서 지우며, 같은 로컬 서버로만 Bearer 인증을 보냅니다. 서버 로그·URL query·프로세스 명령 인자에는 키를 넣지 않습니다.

브라우저가 자동으로 열리지 않으면 실행 창의 `/pc` 주소를 열고 `access-token` 파일 내용만 접속키 칸에 입력합니다. 다른 사람에게 접속키 파일이나 브라우저 세션을 공유하지 마세요. `연결 해제`는 브라우저 세션의 키와 표시 카드를 지웁니다. 서버는 `127.0.0.1`에서만 수신합니다.

Python만 사용하는 실행도 가능합니다.

```bash
python scripts/launch_pc.py --port 8765 --data-dir ./private/pc
python scripts/launch_pc.py --no-browser --port 0 --data-dir ./private/pc
```

## 화면 사용

내 챔피언 → 상대 라이너 → 적 정글러 → 조합 순서로 입력합니다. 내 포지션을 정하면 상대 라이너와 팀 역할을 구분할 수 있습니다. 모르는 칸은 비워 둡니다. 수동 입력은 항상 미검증이며 출처 검증으로 승격하지 않습니다. 폼을 수정하면 자동 반영을 끄고 현재 수동 입력을 사용합니다. 자동 반영 체크를 켜면 다음 클라이언트 선택 정보를 사용합니다.

자동 연결은 선택·확정·역할·밴·단계만 사용합니다. 계정 식별 정보를 화면에 표시하지 않습니다. 로컬 클라이언트의 명시 연결 및 인증서 확인이 준비되지 않으면 수동 모드를 유지합니다. 자동 선택 중 연결이 끊기거나 선택 단계를 벗어나면 이전 카드를 즉시 숨기고 수동 폼을 보존합니다. 게임 시작 시 경기 전 카드를 숨깁니다. 단계 미확인 상태에는 전술을 표시하지 않습니다. 전체 공식 한국어 설명은 아래 참고 자료에서 볼 수 있습니다.

첫 화면에는 관련 전술 최대 세 개와 내 챔피언 공식 설명을 표시합니다. 다른 조언과 공식 설명은 `다른 준비 조언·공식 설명`을 펼쳐 볼 수 있습니다. 카드는 처음에 최대 세 줄과 근거 등급을 표시하며 긴 줄의 전체 문장은 상세에서 확인할 수 있습니다. `상세 설명 · 근거 보기`를 펼치면 조건, 패치 상태, 안전한 HTTPS 출처, 원문 해시를 확인할 수 있습니다. `미검토 가설(AI 작성, 근거 링크)`은 확인된 전술이 아닙니다. 자동 검토 카드의 `이 자동 검토에 이의 제기` 버튼은 실제 클릭 후 사유를 입력해야 기록됩니다. 이의가 기록되면 해당 후보를 다시 투영한 카드에서 제외하며 기존 USER 승인 이력을 바꾸지 않습니다.

공식 자료는 서버에서 매일 갱신 여부를 확인합니다. 주간 점검은 화면 아래의 펼침 항목에서 주차와 최대 다섯 건의 요약을 보여 주는 로컬 보고서이며 사용자가 후보 전체를 검토할 필요가 없습니다. 자동 검토는 출처와 반례의 한정된 검사이며 코칭 정확도를 보장하지 않습니다.

## 재현 검증

```bash
python -m unittest tests_pregame.test_pc_launcher -v
python scripts/browser_pc_v21.py
```

브라우저 검증은 격리된 합성 입력과 실제 로컬 서버/Chromium을 사용합니다. 입력 이벤트부터 카드 DOM 표시 후 다음 프레임까지 `performance.now()`로 측정한 시간을 기록합니다. 합성 자료를 실제 경기 결과나 실제 Windows PC 검증으로 보고하지 않습니다. 실제 사용자의 승인·GitHub 댓글은 생성하지 않습니다.
