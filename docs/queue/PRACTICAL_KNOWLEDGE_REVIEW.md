# 실전 조언 지식 검토 — 2026-10-14

사용자 결정에 따라 기존 350개 후보 파일은 그대로 보존하고, PC 기본 검토 대상은 별도 실전 조언 30개로 바꿨다. 예시 조합 10명과 자주 하는 유나라·애쉬·카이사·케이틀린을 포함한다. `knowledge_candidates/practical-review-v1.json`은 기존 후보 ID·원본 명세 해시·공식 자료 URL/항목/파일 해시를 보존한다. 각 조언은 상황 / 할 것 / 하지 말 것 / 상대 권리 / 무효 조건 / 근거 / 패치로 구성했다.

공식 기술 설명을 한국어로 요약한 사실과 그 사실에서 도출한 행동 제안을 구분한다. Q15 자원 통계는 교전 승패·인과·최적 선택의 근거가 아니므로 전술 수치를 붙이지 않았다. 전문가 수동 요약은 연결된 근거가 없다. 공식 자료 버전은 16.20.1, 사용자가 검토할 경기 적용 범위는 16.20이다. 현재 경기 패치를 추정하지 않는다. 패치 미입력 카드는 계속 미확인이다.

새 댓글에 `승인 KR-001 KR-002`, `거절 KR-003`, `수정 KR-004: 바꿀 내용`을 적는다. 한 댓글의 여러 결정은 줄바꿈 또는 ` / `로 구분한다. 묶음에 없는 ID, 중복 ID, 알 수 없는 문장, 다른 작성자, 편집한 댓글은 가져오지 않는다. 정정은 새 댓글로 남긴다. 수정은 승인 없이 새 미검토 버전으로 저장하고 PC에서 다시 검토한다. PC에서 내용·범위를 바꾼 후보는 옛 이슈에 대한 승인으로 덮어쓰지 않는다. 같은 내용의 승인 뒤 거절처럼 새 댓글의 명시적 결정을 반영할 수 있으며, 이전 결정 이력은 보존한다.

PC `/review-queue`의 **GitHub 결정 가져오기** 버튼으로 현재 서버의 동일 연구 DB에 반영한다. 서버와 CLI의 일반 인증은 기존 방식을 유지한다. GitHub CLI `gh`가 설치되어 있고 저장소 이슈를 읽을 수 있어야 한다. 원격 호출은 등록된 이슈 댓글에 대한 GET만 사용한다. 웹 호출의 본문은 빈 객체이며 임의의 결정·작성자·댓글 원문을 받을 수 없다.

서버를 종료한 상태에서는 동일 `--db` 경로로 실행한다:

```sh
python scripts/import_github_review.py --db private/work.sqlite
```

GitHub 승인·거절은 기존 `knowledge-decision.v1`과 동일 SQLite 테이블/정확한 버전/선택된 원본 해시/CAS/출처 결속을 사용한다. 기존 `USER_WEB` 저장본의 바이트는 변경하지 않는다. 새 채널은 `USER_GITHUB`와 `github_comment` 감사를 추가하며 둘 다 사용자 결정이다. 감사에는 URL·작성 시각·편집 시각·원문·작성자·원문 해시가 들어간다. 수정 요청도 불변 연구 자료로 원문을 보존한다. 일반 백업은 이 자료와 결정 행을 함께 보존하며 재시작 시 검증한다. 한 댓글의 결정 전체와 가져오기 영수증을 단일 트랜잭션으로 반영해 중간 실패와 중복 반영을 막는다.

[AGENTS.md](../../AGENTS.md)는 Codex와 하위 에이전트의 결정 이슈 댓글 작성과 이슈·댓글 수정·삭제 등을 금지한다. 같은 계정의 사람/AI 구분을 암호학적으로 보장한다고 주장하지 않는다. AI 생성 후보는 승인 전 상태이며 실제 사용자 결정만 승인·거절로 반영한다.

가져오기 결과와 PC 화면은 예시 조합의 5포지션 × 9카드 = 45칸 중 실제 적용된 칸을 보고한다. 경기 패치 미입력 결과와 16.20을 명시한 예시 결과를 별도로 보여 주며, 지식 승인 수를 채워진 카드 수로 바꾸지 않는다. 일부 승인만으로 미확인 공통 지도·이동·운영 칸이 모두 채워지지는 않는다. 상대 권리의 문장과 별도의 통계 기반 위험/안전 판정도 구분한다.

최초 실제 조회는 세 이슈 모두 댓글 0, 사용자 결정 0, 카드 0/45였다. 가상 댓글·브라우저 검사의 결정은 이 숫자에 포함하지 않는다. 검증 근거는 `evidence/queue/practical-review-20261014/`에 보존한다.
